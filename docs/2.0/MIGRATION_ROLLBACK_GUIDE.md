# MVU Auto Doctor 2.0 迁移与回滚指南

适用候选：`2.0.0-rc.21`（测试仓；未完成正式门禁）

## 在线发布通道

`2.0.0-rc.21` 当前只进入独立测试仓 `main`；正式仓和正式 `main` 保持不动。完成真实门禁前只能用于用户自测。
已有安装只需点击“MVU 自动医生”这一行自己的“更新”并刷新；全新
安装才使用仓库地址 `https://github.com/magilittle0-byte/mvu-auto-doctor-testing` 并将分支或标签
留空。

以下备份与向前回滚流程是 rc.1 在线发布留下的历史通道，不是 rc.14 已上线的证明。

### rc.21 人物档案迁移与回滚

- 新聊天默认使用“正文语义块 → MVU”；`/人物档案/byActorId` 是唯一完整内容权威，ActorLedger 只保存引用和 readiness。
- 旧聊天的 verified profileV6 默认只读可用，不自动重写。设置页“迁移旧档案到 MVU”会逐 Actor 复制、写入、回读，再切换该 Actor 的 profileRef；失败 Actor 保留旧档案且不产生半档案。
- “人物档案来源路径”切到“旧 P1 模型链”是明确回滚开关。回滚不删除 MVU 档案，也不双向同步两份内容。
- 迁移后如需回退，只切回旧路径；不要手工删除 `/人物档案`、旧 profileV6、ActorRegistry 或历史回执。

### rc.14 后台恢复与身份/存储迁移

- rc.13 的 sovereignty runtime 与 inline checkpoint 自动迁移到 runtime v4 / checkpoint v3；稳定 actorId、别名、谱系、知识、资源、证据、档案和历史回执保持原样，重复执行迁移得到相同内容与字节。
- 旧 inline payload 会先按内容重算 SHA-256，再按人物账本、连续性和世界压力拆成共享 blob 与小 manifest；GC 只清理当前检查点、未决任务和失败恢复基线均不可达的 blob。单个不可压缩状态超过预算时保留最后可恢复检查点并明确显示超预算，不静默删字段或回执。
- 正常回合先 durable 保存 observation WAL，人物/世界/来源回执随最终单一命名空间事务提交；中间人物子任务可由 WAL 中的父任务确定性重物化。最终保存失败不宣布成功，刷新后从已落盘 WAL 恢复。
- `retryable_failed` / `deferred` 任务若因旧人物回合时钟得到大于当前观察游标的 `nextRetryTurn`，会改为当前 `observedThrough`，恢复模式固定为 `latest_state`。
- 恢复只从 claim 时固定的 observation cut 重新生成对应人物尝试与世界候选；之后到达的正文另开未来任务，不补造或回填过去已经发生的行动、秘密关系、能力资源或玩家经历。
- 最新状态提交覆盖到当前观察游标时，同模块被覆盖的旧待办改为 `cancelled_stale`，并保留覆盖回执和检查点。
- 已经由用户主动取消的终态任务不会因刷新或迁移重新启动。

### rc.12 人物主权状态迁移

- 保留稳定 actorId、别名、谱系、知识、资源、证据与历史 action receipt。
- Actor Ledger v5 自动升为 v6；连续性 `nextBeat` / `trigger` 不再复制进人物目标，而转为刺激。
- 空白档案进入所选补全模式的队列；首次正式行动前必须达到该模式的档案门。
- 旧事件结果不会补造为历史行动；未披露的后台结果保持隐藏。
- 旧的模型/解析失败不会迁移成人物沉默，新的技术计数只存在于 sovereignty runtime。
- `deceased`、`departed` 和 `dormant` 状态继续保留，并在新正文证据到达时重新核对。
- 灰度模式为 `legacy`、`shadow` 和 `active`；shadow 只形成候选与检查点，不提交人物/世界事实。
- rc.10/rc.11 已有 V6 档案、actorId、别名、谱系、知识、资源、证据与历史回执原样保留；rc.12 只补齐空白档案、个人计划和字段来源，不补造已发生行动、秘密关系、能力资源或玩家经历。
- rc.10 的 pending/retryable_failed backlog 原样恢复；超长世界任务在新总时限内重新生成，绝不补算虚构的旧行动。

`codex/backup-main-pre-v2.0.0-rc.1-20260727`，对应提交
`7d761ba6af1ceb10ab3ea5947c0bb25ee1b72566`。若 RC 出现恶性问题，维护者从该
快照在当前 `main` 之上创建一个“树内容等于旧版”的向前回滚提交；用户随后仍只需
点击自动医生这一行的“更新”。这避免让只能在线更新的客户端执行历史倒退或依赖
分支列表。数据库、骰子前端、缝合怪、推进重roll助手、聊天和角色卡均保持原位。

## 迁移原则

2.0 不批量重写旧聊天。首次读取 1.x 数据时，医生建立只读 V2 sidecar 投影；1.x
聊天仍是可读回退源，未知作者字段保留在 `extensions.legacy`，歧义数值、槽位、
资源、关系和任务状态显示为 `unresolved` 或 `quarantined`，不会被猜测或结算。

升级前请保留原聊天备份。升级演练会核对聊天摘要、对象数量和序列化容量，生成迁移
诊断与回滚收据，但不会把诊断当作生产写入。只有 `valid/mapped` 记录可进入 V2
事务；其余记录继续以 1.x 只读形式显示。

### rc.9 本地状态迁移

- 聊天 namespace 升为v11；旧字段与第三方字段原样保留。
- Actor Ledger 升为v5，旧人物ID不重算。v2 新增的 `lineage`、`inactiveReason` 与
  `departed/deceased` 状态继续使用惰性默认；v3 增加社交、决策、说话与压力应对
  风格、日常习惯和盲点。v4 的动态人格证据继续保留；v5 新增人物约束、世界状态事实、
  最后语义行动与连续失败计数。旧的玩家依赖目标会迁移到约束，不会因此冻结人物自己的行动。
- 连续性设置升为v7。旧“世界接口”值迁移为“注入数量”；新增势力槽1、环境槽1、
  压力上限3、同场首领上限1和均衡恢复节奏。所有选项只控制医生自己的后台模拟。
- 新增 `worldPressure`、世界槽收据和注入阶段收据。旧聊天没有这些字段时从空状态
  开始，不回写历史正文，也不推断过去威胁。
- 新增 `serendipity` 许可证账本。它从空状态开始，不回放历史抽取；只有当前完整
  message/swipe/generation/branch 身份结算后才写入。设置只新增四个自然语言选项。
- `socialMonthlyCostLedger`、旧币种阈值及其他未知旧设置仅兼容读取并原样保留：rc.9
  不使用、不规范化、不迁移、不阻塞，也不主动删除这些用户未知数据。
- 回滚到rc.4时，rc.4会忽略新增字段；不得为了降级删除v11 namespace或人物谱系，
  以便再次升级时保留审计证据。

## 升级演练

1. 在设置页环境自检确认 API v5、持久存储、精确读写和保存回调均可用。启用
   TavernDB 时无需修改或注册医生协议；无合作 API 时将它视为非托管第三方，
   外部写入一致性保持未知，但不阻断医生迁移。
2. 对选定聊天执行只读迁移诊断，检查 `mapped/unresolved/quarantined` 计数。
3. 确认旧聊天正文、swipe、未知扩展字段和原有 1.x 状态仍可读取。
4. 只对 mapped 记录启用 V2 sidecar；不得把 unresolved 记录手工改成已结算。
5. 刷新并重载同一聊天，确认 barrier、幂等、恢复和最终指纹仍可读取。

自动演练入口是 `prepareLegacyUpgradeDrill()`。默认上限为 256 条领域记录和 8 MiB
聊天投影；该边界除既有57消息真实记录外，又用65消息、48个swipe、约3.5 MiB合成
旧档做只读演练，未知字段、TavernDB字段、推进重roll助手V2字段和当前swipe来源身份
全部保留，摘要回滚通过。超过上限仍会进入 `fallback`，保留旧聊天，不产生部分
V2 sidecar。

## 回滚

回滚必须使用升级演练生成的只读快照与 SHA-256 摘要：

1. 停止对目标聊天的新 V2 事务，并等待当前任务进入终态。
2. 核对聊天、消息、swipe、generation、branch 和内容指纹。
3. 调用 `rollbackLegacyUpgrade()` 验证快照摘要并移除 V2 权威 sidecar。
4. 恢复 1.x 只读视图；不得删除未知旧字段或物理删除审计记录。
5. 若已有事务写入，使用阶段2/6恢复记录，只恢复仍等于本事务写后值的路径。
6. 重新加载聊天并确认正文、旧字段、论坛/连续性计数和当前分支可读。

摘要不匹配、身份歧义、目标已切换或当前路径被合法外部更新时，自动回滚必须停止；
保留恢复记录，转人工审阅，禁止覆盖最新楼层。

## 降级边界

降级后可以读取 1.x 聊天和旧扩展字段，但 2.0 独有的分支、事务、事实/知识、
TaskLease 和 barrier 只作为审计 sidecar 保留。1.x 不会执行这些 V2 记录，也不会
隐式合并分支。维护者确认回滚结果前，不应删除 V2 审计数据。
