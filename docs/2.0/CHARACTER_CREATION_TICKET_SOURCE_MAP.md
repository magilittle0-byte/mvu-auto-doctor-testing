## 项目内成熟链复用

- 原样复用阶段1权威顺序：生成前票据 → 正文 → ActorCandidate → ActorRegistry/ActorRef → 完整档案事务 → 行动就绪。
- 原样复用阶段2的 `ProfileInsertCandidate`、本地格式修复、候选验证、单次原子保存、digest/commit/readback；阶段4没有新增第二套档案写入。
- 原样复用阶段3的候选发现顺序、注册状态机、聊天隔离 ActorRef 和注册持久化；票据只在注册成功后、档案准备前插入同一事务链。
- 最小适配旧字段 `profile.designRolls`：它仅作为持久化兼容槽位，提示词和运行时对象统一称 `characterCreationTicket`。V1 已保存票据可读取，不能触发新骰。

## 阶段4必须新写的部分

- V2 票据发行身份与绑定收据：参考本体没有 SillyTavern 的 chat/message/swipe/generation/branch 目标语义，也没有本项目 ActorRef，因此必须新写精确绑定层。
- generation 批次暂存与迟到隔离：参考本体没有宿主重生成、换 swipe、换聊天和迟到回包时序，因此必须按本项目运行时目标新写。
- 新增的本地轴与种子文本：参考作品提供成熟结构和行为约束，但其原文不作为可移植代码池；本项目为核心欲望、思考方式、社交动机、利益取向、冲突方式、道德边界、行动习惯和自我欺骗补写本地种子。
- `discardedAxes` 收据：优先读取现有 ActorRef/profile/MVU 的明确结构化字段，记录低优先级票据轴被上层事实逐轴压制，不修改票据 ID，也不生成折中人格。
- 自由 worldContext 没有成熟语义字段映射。本阶段只做最小适配：同一文本片段必须出现人物名，并以规范轴名加 `：`/`=` 明确声明，才丢弃该同名轴；普通叙述、同义词和模型推断一律不触发。它只能识别显式标注，不能声称理解了自由文本的完整人格语义。

## 所有权边界

- 脚本只在正文生成前发行票据；预设只在生成时消费票据塑造首次出场。
- 医生在正文后只按完整目标和 ActorRef 绑定、验证、保存同一票；缺票保持缺失，不能重掷。
- 原著、角色卡、世界书、数据库确认档案、既有 ActorRef 和 MVU 锚点受到保护；票据只补真正空白。
- 数据库继续从最终接受正文独立填表；MVU继续持有实时变量；缝合怪继续持有未执行规划；阶段4不新增内容外审或模型提示入口。
