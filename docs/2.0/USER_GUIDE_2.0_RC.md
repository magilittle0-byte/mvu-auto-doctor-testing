# MVU 自动医生 2.0 RC 使用说明

> 阶段一模块独立化：TavernDB 等第三方脚本不需要注册医生的 barrier 协议。
> 旧 settlement API 保留兼容签名，但立即返回 `independent_modules_no_global_settlement`，
> 不读取回执、不等待，也不把数据库或其他模块作为医生成功条件。

适用版本：`2.0.0-rc.30` 测试候选

> 阶段一入口调整：只有 SillyTavern 最终接受且正文非空的 AI 回复才分发医生后处理。
> 聊天加载、切换、刷新、流式片段、生成中消息、停止生成和空占位均不会启动任务。
> 旧平行提示词注入与无限自动恢复暂时停用；旧配置和账本只兼容保留，各模块失败仅保留明确手动重试边界。

> 阶段二人物档案模块已从旧 combined continuity 中独立：最终接受正文只自动运行当前来源的人物登记与整档，
> 历史欠档不会在刷新、重启或加载聊天时自动恢复。公开 `runContinuity` 是阶段三的单批世界入口；它不会执行人物 discovery、Registry upsert/promotion/readback 或 profile completion。人物档案的公开入口是 `runActorProfiles`。每段合格自然正文固定
> 一次联合“发现新人物 + 填完整档案”调用，即使没有人物也由该次调用明确返回 `[]`；模块关闭、空正文和机制-only 正文才是 0 调用。

这是 `2.0.0-rc.30` 测试候选的安装与更新说明。本候选已修复 rc.29 真实宿主加载时发现的入口语法阻断，并通过定向 ES module 解析回归和完整自动套件 663/663；十二回合正式门禁仍必须在 rc.30 当前指纹下执行。rc.30 保留 `full_adult` 六项生理完整度、MVU 唯一权威、A/B/C/D 长期运行链、projection recovery 和 prompt-ready 隔离，数据库、预设、MVU 与 Doctor 权威边界不变。真实测试必须在当前 loaded fingerprint 下于同一聊天连续完成十二个有效回复：正常正文不 reroll，Doctor 故障在同一 accepted SourceRef 上修复，只有正文硬失败才替换当前回复。正式发布仍要求真实目标模型生产全链、真实
SillyTavern、作者版 TavernDB、隐藏 TauriTavern、PR 与 CI 全部通过并实际进入默认 `main` 后，酒馆才可直接
使用默认 `main` 更新，不需要加载分支列表；本仓库生成的 rc.14 离线包仍可用于手动安装或回滚演练。若更新时页面仍显示旧版本，
先刷新酒馆再只点击自动医生这一行自己的“更新”，不要对其他扩展执行批量操作。

rc.14 沿用人物账本 v6 和“世界、人物与事件”悬浮面板，并补齐 typed ActorRef、真实档案覆盖、逐人物持久任务、人物尝试/世界裁决、正文消费回执、内容寻址检查点和按字节预算。阶段一不再让人物、世界、社交、论坛和变量任务无限自动恢复；实际运行中的模块仍可主动取消，失败不会伪造成完成或处理中，用户可从对应模块明确手动重试。正文生成不等待这些后处理。人物档案覆盖率要求身份、人格、关系、目标、知识、资源能力、动态状态和行动历史均有真实来源或明确的空集合语义：
正文先由本地持久观察，模型失败只进入技术 backlog，不会变成人物沉默；连续性下一拍只成为
刺激、机会和风险，人物自行决定是否采纳。人物的前台行动只注入意图或尝试，后台成果默认
隐藏，玩家行动、同意、参与和感受永远不会由医生结算。除社交、决策、欲望、边界、习惯与盲点外，档案还会按来源保留
信息取样与典型误读、具体关系中的距离、自我形象和实际行为的缝隙、训练形成的逆倾向能力，
以及受压反应和恢复路径。MBTI、九型、Tritype、依恋型等分类不会直接写进人物档案；一次
恐惧、愤怒或绝望也不会覆盖整个人格。低概率偶发变化继续受玩家主权、角色卡、原作锚点、压力和最低可玩性保护。所有设置只控制自动医生
自己的后台模拟和注入：不会截断、重写或重生成 `<content>`，也不会要求角色卡、
数据库、缝合怪或骰子前端采用医生私有协议。真实环境结果与发布状态以本次候选的
发布收据为准，旧版本的成功记录不冒充 rc.14 证据。v6 会把必须由玩家完成的条件留作约束，
同时继续调度人物自己的调查、准备、联络、移动和资源变化；只有落下具体世界状态事实才算语义推进。

## 1. 从现有版本升级

1. 用酒馆自己的聊天导出/备份功能保存要测试的长聊天，并等待当前自动医生任务
   结束；聊天、角色卡、数据库和其他脚本保持原位。
2. 候选阶段使用 rc.30 测试仓更新自动医生自身文件，并另行导入配套预设；不要覆盖数据库或其他扩展。
3. 只有测试仓 `main` 的 manifest 已明确显示 rc.30 后，才只点击“MVU 自动医生（测试通道）”
   这一行自己的“更新”按钮；不要点“全部更新”，也不要点击分叉/分支图标。
4. 更新完成后刷新酒馆，扩展信息应显示 `2.0.0-rc.30`。如果仍显示旧版，先保留
   当前页面和控制台信息，不要删除扩展或反复切换分支。
5. 打开自动医生设置，先运行环境自检，再检查严格变量通道和轻量通道所选的
   API 预设、模型、代理方式与“同时请求数”。两个通道可以共用一个连接，也可以
   分开配置；严格通道默认同时 2 个，轻量通道默认同时 4 个，均可在 1—8 间调整。
这次操作只更新 `mvu-auto-doctor` 自身。其他扩展和脚本都保持现状；
不要点击它们的更新、分支、删除或重装按钮。

### 全新在线安装

尚未安装自动医生时，打开“扩展 → 安装扩展”，填写：

```text
仓库地址：https://github.com/magilittle0-byte/mvu-auto-doctor-testing
分支或标签：留空（默认 main）
```

选择“仅为当前用户安装”（单用户环境直接选择“安装”），完成后刷新页面。

## 2. 和现有脚本一起使用

数据库本体、可视化前端、骰子前端、缝合怪、推进重roll助手V2，以及其他
已经调好的脚本都可以继续启用，不需要为了测试自动医生而删除或重装。

- 自动医生只使用自己的 `mvuad-*` 控件和扩展存储，不会覆盖推进重roll助手的
  `reroll-helper-btn`、`Reroll_Global_Settings` 或 `Reroll_Cache_*`。
- 第三方数据库可以完全不调用医生 API。旧 settlement 查询仅返回“独立模块、无全局结算”，
  不读取旧回执、不等待或汇总任何模块；数据库仍按最终接受正文独立运行。
- 不要导入或启用旧“数据库最终正文桥”。`2.0.0-rc.2` 起已从发行包删除该桥；
  旧安装若仍有同名 TavernHelper 条目，应禁用或删除。数据库每轮只读取接受的
  `<content>` 独立填表，不等待变量医生，也不在变量写入后重复填表。
- 不要重新启用旧 `spv8.4` 源码改写脚本。作者数据库升级时只改作者原版入口的
  版本标签；独立桥无需跟着改数据库版本，也不要把两段脚本重新拼成一个加载器。
- 推进重roll助手触发重生成后，自动医生会重新核对聊天、消息、swipe、
  generation 和正文指纹。旧回复上的医生任务会变成 `stale`，不能污染
  新分支。
- 骰子结果、装备槽位、资源消耗和 MVU Schema 仍以角色卡与启用世界书的明确
  合同为准；自动医生不会猜字段，也不会改写骰子前端或缝合怪文件。

正常使用时可以直接点推进重roll助手。若悬浮工具页正显示任务执行中，建议先
观察该任务完成或取消后再重roll；即使直接重roll，旧任务也必须被稳定屏障拦住，
不会落到新回复或数据库里。

### 数据库的安装顺序

1. 停用旧的数据库源码改写兼容层，保留作者原版数据库本体。
2. 将作者原版数据库入口按作者公告指向当前版本，并确认它单独可以加载。
3. 不安装任何会在医生结算后调用数据库通用更新入口的桥接脚本。
4. 刷新酒馆，确认作者数据库本体能独立处理每轮 `<content>`。医生环境自检中
   未注册的第三方数据库显示“未知/非托管”是信息状态，不代表错误。

## 3. 日常使用

1. 正常发送消息并等待 AI 回复被 SillyTavern 最终接受。只有正文通过既有自然正文 eligibility 门时，
   人物档案模块才接收同一 chat/message/swipe/generation/scope/content 目标。纯 JSONPatch、选项或机制块
   不会触发人物登记。合格自然正文无论最终发现 0、1、3、6 或更多新人物，都只发出一次正常联合填表调用；
   0 人必须由该调用明确返回 `[]`。流式片段、生成中消息、聊天加载回放和空占位不会启动后处理；数据库仍独立填表。
2. 点击悬浮球“脉”打开“世界、人物与事件”面板；世界、人物、事件、论坛和工具页使用同一聊天上下文。
3. 点击“人物”，在下拉框选择角色即可查看九类档案。每个字段都会显示“已确认/医生设计/待确认假设/已弃用”来源；可以锁定整个人物、单个模块或字段，也可手工覆盖。手工覆盖和锁定值在后续自动补全后仍保持，修改会进入版本历史。
4. “人物”页人数为0时表示当前聊天尚未登记稳定人物，不代表只剩事件；具名人物被正文、角色卡或世界书识别并完成迁移后会出现在下拉框。
   本回合所有新登记人物不受“历史档案手动维护预算”截断，会进入同一次初始批量调用；正常没有“三人上限”。
   新人物行必须给出正文中逐字存在、且只出现一次的 `sourceAnchor`；医生从未改写正文计算真实顺序，再按 candidateId
   走 Registry promotion 并重键 ActorRef，不按姓名或数组位置猜人物。
   如果 Registry 已保存而整档失败，可点“重试当前正文人物档案”；它只精确恢复当前来源，不按姓名猜人物。
   “补全人物档案（含历史欠账）”才会在同批加入受预算限制的旧欠档。
5. 变量存在可证明问题时，补丁先在内存中校验，再精确写入当前楼层并回读。
   本阶段入口不会修改玩家正文，也不会创建、覆盖或切换正文 swipe。
6. 危险的导演动作必须显示目标和影响范围并由你确认。没有宿主桥或证据不足时，
   页面会显示 `unresolved`，不会直接写状态。
7. 内置论坛默认手动刷新。它读取本轮接受的正文并独立运行，不阻塞变量医生或
   数据库；重载页面后主题和评论应继续存在。
8. 工具页的操作时间线可以查看任务阶段、取消与失败原因；默认诊断只记录 verdict、
   数量、错误码、哈希和必要耗时，User-Agent 只保留平台与内核大版本，不包含剧情
   摘要、finding/decision理由、私人聊天、完整提示词、密钥或原始请求载荷。
9. 人物二审不再估算人民币/美元价格，不维护月度金额、软提醒或隐藏硬上限，也不会
   因旧账不完整停止调用。费用由你在所选服务商处自行管理。诊断只记录调用次数、
   成功/失败、HTTP状态、重试、耗时，以及上游实际返回的 input/output/cache token；
   上游不返回 usage 时保持0，不按字符估算。HTTP失败、超时或结构无效时零关系写入，
   不会统一 revert 或删除路径。
10. 变量检查默认在首次失败后重试3次，可在变量诊断的模型适配折叠区设为0—5次。
   默认最多4次模型调用，但仍是一个自动主任务、一条终态记录；切聊天、重roll、
   新 swipe、取消或目标过期会立即停止剩余重试。最终失败会显示尝试次数、失败步骤、
   零写入状态和处理办法，可以直接修正连接/规则后检查当前回合，无需重roll正文。
11. 严格和轻量通道的并发池彼此独立；共用同一个端点与密钥时也不会互相占槽。
   人物分片、人物关系二审、世界连续性和论坛共享轻量池。数字越高，后台任务越快，
   但也更容易碰到供应商的并发或频率限制；遇到 429、拥堵或本地代理性能不足时，
   逐步调低即可。这里放开的只是模型网络请求，变量和账本持久写入仍然串行复核。
   若用户明确选择酒馆当前连接，医生会固定串行以避免宿主冲突。

### 看懂错误提示

- `MVU 内部“正在分析”标记持续未释放`：正文已生成，数据库也可以已经填完；医生
  等的是 MVU 自己的占用标记，不是数据库。先检查是否重复启用了 MVU/变量脚本；
  若变量快照已经持续稳定，医生会自动继续，否则刷新酒馆后直接检查当前回合。
- `模型调用失败`：先在“模型通道”测试严格通道，核对 API 地址、密钥、模型名与
  网络；限流时等待或降低重试次数。正文与变量不会因失败被改写。
- `输出被截断/没有 UpdateVariable`：提高 `max_tokens`、换格式遵从性更强的模型，
  或在模型适配提示中强调只输出变量补丁；直接检查当前回合即可。
- `补丁未通过校验`：查看拒绝路径及类型/范围/删除原因，核对角色卡 Schema 与规则。
  医生不会写入不合法补丁。
- `人物档案未完成`：档案模型运输、格式/语义、ActorRef、保存或 readback 中至少一段未完成；失败人物不会留下半张档案。
  档案会先以 pending/not-ready 整批保存并读回，再从该次真实读回构造 finalize，最后再次读回；任一阶段失败都不会把 pending
  或未认证 final 当作行动就绪。修正轻量通道后可重试当前正文；只有看到“整档已原子保存并回读验证”才表示人物达到行动就绪。
- 世界或论坛错误会明确说明处理入口，并注明它们不阻塞正文、数据库或关键变量结算；
  人物关系二审错误会明确注明失败零写入、关系变量保持不变。

### 同一回合多个世界事件（阶段一注入停用）

- “活世界与事件连续性 → 每回合最多进入正文的世界接口”及其历史事件批次设置仅为旧配置
  兼容保留，阶段一禁用且不会创建新的正文注入批次。
- 人物档案模块在最终正文接受后独立登记和整档；世界模块在阶段三前固定延后，不创建世界候选、人物行动、agent pool
  或下一回合注入。旧历史不会被清空或重写。
- 这些能力等待阶段四通过唯一的缝合怪提示词入口重新接入；阶段一不搬迁、重排或替代旧注入。
### 人物/世界旧设置与阶段二边界

- 当前自动后处理只由独立人物档案入口负责一次联合 discovery/整档、Registry、同票条件绑定和 pending → finalize 双 readback。
- 联合调用会看到当前作用域全部已登记人物的紧凑 ActorRef/别名索引用于精确去重；只有本 source 未完成人物与用户明确启动的 maintenance 才是详细整档目标，其他历史欠档不会被自动带入。
- 旧账本缺空 scope 标识时，医生以宿主原值做 CAS，只在当前 scope 已 fresh 证明的合法写事务内最小补入；非空 scope 冲突仍会拒绝写入。
- “人物行动人数、次要人物探索槽、势力槽、环境槽、主动碰撞强度、恢复节奏、世界连续性提示”等均为后续世界阶段的兼容配置；阶段二不读取它们来启动模型、人物行动、世界结算或注入。
- 旧 combined continuity 执行体已停止；`runContinuity` 与设置页世界按钮仅进入当前 P3 单批世界链，不会重接人物 discovery、Registry upsert/promotion/readback、profile completion、barrier 或旧注入。
- 人物档案模型只使用全局提示入口中适用于 profile/fast 的配置，以及既有的字段、权威事实、同票和共享正文材料。它不增加内容审查，也不替玩家决定行动、感受、同意或关系结果。
- 票据只条件消费当前同 generation 已存在的 Stage4 批次；阶段二不签发、不补掷、不重掷，也不恢复旧注入。没有票或票池耗尽时仍完整生成 hypothesis 档案并明确提示。
- refresh/restart/CHAT_CHANGED/CHAT_LOADED 只从宿主 actorLedger 读回；行动就绪会核对当前人物的 profile digest、ActorRef/schema/locks/manualOverrides 与持久 transaction/write-set/commit evidence。整批 pending 投影仍只在原子 final/readback 当下严格重建，避免同批其他人物后来合法维护反向废掉旧档案；不能只信档案自带的成功字段，也不会自动 discovery 或补历史欠账。
- 手动“重试当前正文人物档案”只处理当前捕获来源；手动“补全人物档案（含历史欠账）”才会在当前初始人物之外加入受预算限制的维护候选。

### 世界惊喜与偶发许可证（阶段一停用）

- “世界惊喜频率”“最大惊喜幅度”“好运坏运倾向”“谜团解释速度”等旧设置仅兼容读取，
  当前界面保持禁用；阶段一不抽取、不签发、不注册、不保存新的偶发许可证。
- regenerate、swipe、continue 或普通生成都不会启动旧许可证注入。既有许可证历史只读保留，
  不会在聊天加载、刷新或切换时迁移、清空或重新执行。
- 偶发事件若在后续恢复，只能等待阶段四通过唯一的缝合怪提示词入口接入；阶段一不提供
  替代注入，也不让许可证成为正文、变量、数据库或其他医生模块的等待条件。

## 4. 推荐的 RC 共存测试

以下是后续统一验证清单，不是阶段二完成证明。阶段二按审计要求只做静态源码、调用图和差异检查，
没有运行单测、语法、JSON、API、真实模型、SillyTavern/Tauri、浏览器、构建或 CI。

请用一份已备份的现有长聊天完成下面这组测试：

1. 打开1.x时期的聊天，确认旧消息、数据库状态和角色卡仍可读。
   当前候选已验证65消息、48个swipe、约3.5 MiB的合成旧档回归；默认迁移窗口为有界
   8 MiB，超过上限会保守回退为1.x只读视图。
2. 正常生成一轮，等自动变量任务显示终态，确认变量补丁绑定当前目标且正文 swipe
   未被医生改写；连续性、论坛和数据库各自读取同一轮接受正文，不互设长时间屏障。
   第三方数据库未提供合作能力时只验证共存，不声称其受医生事务控制。
3. 再生成一轮，并在医生仍在处理时使用推进重roll助手V2；确认旧任务变为
   `stale` 或被取消，新回复没有混入旧分支的正文、变量、论坛或数据库写入。
4. 检查骰子前端的结果、资源消耗和装备状态没有被重复结算。
5. 检查缝合怪、数据库可视化及其他现有脚本仍能打开，控制台没有新增错误。
6. 在手机宽度打开悬浮页和论坛，展开、收起帖子，确认没有横向溢出。
7. 刷新页面，确认聊天、数据库状态、论坛主题和评论仍然存在；医生对相同
   message/swipe/generation/branch/content fingerprint 不重复执行，旧分支终态历史
   和世界注入收据仍可审计。
8. 若启用NPC分片，分别用1、3、5个worker验证额外调用上限；在worker运行中重抽
   或切聊天，确认旧批次stale，且没有旧分支连续性、论坛或数据库写入。
9. 用空白但没有“明确为空”事实的垃圾堆测试极低概率许可，再用明确确认为空的容器
   验证拒绝；重复换措辞搜索不得多次开奖。若出现好运，确认收益真实且没有自动惩罚；
   若出现重大坏事，确认玩家仍有响应窗口。关闭惊喜后重复一轮，行为应与旧版一致。

若真实结果与上述门禁不一致，请停止继续覆盖测试并按下一节提供脱敏信息；真实
环境结果优先于模拟测试，候选不能因此被放行。

## 5. 回滚到旧版

1. 取消或等待自动医生当前任务结束，并用酒馆界面保存当前聊天备份。
2. 停止继续生成，保留现场并反馈“需要回滚 RC”。维护者已将更新前 `main`
   固定备份为 `codex/backup-main-pre-v2.0.0-rc.1-20260727`，会从该快照向
   `main` 发布一个可正常向前更新的回滚提交。
3. 收到回滚已发布的确认后，只点击自动医生这一行的“更新”并刷新。不要删除原聊天、
   数据库、其他脚本，也不要手工删除迁移审计数据。
4. 若更新失败、摘要校验不一致或旧聊天不可读，停止写入并保留现场，按
   [`MIGRATION_ROLLBACK_GUIDE.md`](MIGRATION_ROLLBACK_GUIDE.md) 的保守恢复步骤处理。

## 6. 反馈问题时提供什么

可以提供：自动医生版本、SillyTavern/TauriTavern版本与提交号、手机或桌面尺寸、
是否使用重roll、可复现步骤、任务状态、控制台错误名称和脱敏诊断包。

不要提供：API 密钥、私人聊天原文、完整提示词、原始模型 payload、包含凭据的
请求头，或整个用户数据目录。
