# 人物主权世界引擎

适用版本：`2.0.0-rc.14`

## 运行边界

医生把“看到正文”和“完成后台模拟”拆成两个持久游标：

- `observedThrough` 只由本地观察推进，不需要模型，也不等待人物或世界任务。
- `simulatedThrough` 只在该回合全部非过期任务达到事务终态后推进。
- 所有失败恢复只使用 `observedThrough` 这一套调度时钟；旧版混用人物回合或模拟回合形成的未来重试会迁移到当前观察回合。
- 每条正文会建立 observation、profile、actor、world，以及按设置可选的 physiology 任务。
- 任务状态限定为 `pending`、`running`、`retryable_failed`、`deferred`、
  `committed` 和 `cancelled_stale`；本地 observation 直接以 `committed` 入账。
- 刷新或重启时，超过硬时限的孤儿 `running` 会转为可重试失败，并明确使用最新状态恢复，
  不补造“本来应该在过去发生”的行动。
- 最新状态恢复提交会把同模块、已被本次状态覆盖的旧任务事务性标为 `cancelled_stale`；这表示旧计算被新状态取代，不表示虚构旧行动已经发生。
- 每次 claim 都固定本次物化的 observation cut；模型运行期间到达的新 observation 不会扩大旧任务的覆盖范围。提交 ID 和检查点 ID 由任务、cut 与内容摘要确定，超时后的同一重试不会生成第二份历史。

每个正常生产回合只有两个必须等待的持久边界：先保存本地 observation WAL，再以一次命名空间事务提交人物账本、连续性、世界压力、来源回执和 sovereignty runtime。checkpoint manifest 将三个大内容域分别寻址并跨模块共享；预算按所有可达 blob 的实际存储字节管理。技术回执的热层按字节受控，较旧记录进入可逆列式 archive，不用固定条数静默截断。

技术失败只影响任务和模块健康。连接、超时、格式、解析、槽位与 Agent 故障会产生技术回执，
但不会修改人物的性格、计划、沉默、知识、关系或行动历史。前台健康灯使用绿、黄、橙、红、
蓝五态，并显示最后成功回合、积压、失败模块和下次重试；“立即重试”和“恢复检查点”均保留
在设置面板和浮动面板中。
技术失败会在后台退避后自动重试，不需要新的聊天消息。排队中的自动重试也会显示取消入口；用户取消后待运行、运行中和可重试任务均进入终态，刷新不会偷偷重新启动。

## 档案 V6

每名人物拥有身份、人格、关系、个人目标、知识、资源能力、动态状态、行动历史和可选生理模块。
字段来源只能是 `confirmed`、`designed_seed`、`hypothesis` 或 `deprecated`：

- 角色卡、世界书和已接受正文中的明确事实记为 `confirmed`。
- 医生为补足可行动人物而设计的初始字段记为 `designed_seed`。
- 不确定推断只能记为 `hypothesis`，不能冒充历史。
- 旧字段被替代后保留为 `deprecated`，便于回滚和审计。

自动补全模式为关闭、基础、完整、完整加成人生理。首次正式行动必须先通过所选模式的档案
覆盖门；新人物的深层字段可以后台继续补全。字段和人物可锁定，人工覆盖优先于自动设计，
单模块可重生成且每次变更保留版本历史。生理模块不反推人格、价值观或道德。

## 人物与世界分权

连续性线程的 `nextBeat` 和 `trigger` 只会成为 observation、stimulus、opportunity 或 risk，
不会写进人物的 `currentGoals`。人物自行采纳、忽略、误读、利用或反对外部刺激。

人物候选的路由限定为：

- `foreground_offer`：向玩家提出请求、邀请、条件或选择。
- `foreground_attempt`：在正文可见范围内提出 NPC 的意图或尝试。
- `background_private`：NPC-NPC 的私下行动，结果默认隐藏。
- `background_public`：可在世界中结算但仍要经过披露规则的公开后台行动。

人物只能决定尝试。世界裁决器根据身份、知识、时间、位置、资源、能力、因果和玩家主权决定
结果。若对象是玩家，只能形成意图、邀请、接近或条件，不能结算玩家参与、同意、行动或感受。
后台成果只有在人物说出、实际使用或玩家发现后才披露；未进入历史的能力与资源不能临时出现。

## 单轮并行协调

默认平衡模式每回合最多选择两名人物和一个世界候选。协调器只运行一个并行轮次，不建立
Agent 群聊，不让 Agent 互相改写。候选写入共享黑板后，由本地确定性裁决器取得最终写权限。
单 Agent、单 API 槽位或整池失败不会阻止其他模块；无法安全裁决的任务进入保守延期。

每个槽位保持自己的模型、接口、预设、凭据引用和宿主路由。分配器根据健康、延迟、失败率
和负载选槽，不使用 API 会话记忆维持人物一致性；一致性来自持久档案与行动回执。

## 自定义指令与诊断隐私

全局补充指令可按档案、生理、人物行动、世界、论坛、社交、变量、严格、轻量或全部调用选择
范围。医生按用户填写的原文逐字注入，不审核、不改写，也不承诺绕过服务商限制。模块专属
指令继续保留。

诊断与导出包不保存全局指令原文，只记录启用状态、范围、字符长度、哈希和本轮是否注入。
凭据、私聊、原始模型请求和响应仍不得进入诊断、报告或发布包。
