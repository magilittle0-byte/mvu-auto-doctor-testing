# 原版说明

这是一个独立的 SillyTavern / TauriTavern 扩展。它包含通用 MVU 审计修复、人物动机与关系证据守卫、分类活世界与事件连续性账本，以及不占正文的内置世界论坛，不会修改角色卡、SP·数据库、预设、缝合怪或其他扩展文件。

2.0.0-rc.17 测试候选把人物档案语义生成前移到配套最新版预设：正文模型输出隐藏的自然中文增量，accepted-final 后由本地脚本绑定同一 characterCreationTicket/ActorId、逐人物编译并通过现有 MVU 事务原子写入与回读。MVU 是完整档案唯一内容权威；Doctor 日常零人物模型调用，只在人工修复时定向补一个失败人物。P3 只读取 MVU durable-ready 档案，P4 在唯一插槽中追加相关人物摘要；数据库继续从最终正文独立填表。紧凑人物档案 accordion 默认全折叠、单人展开、六段分区、故障分色、单人物修复和旧档案迁移；rc.17 额外保证“无变化省略档案块”不会因未消费的预留票池误报失败，真实失败会持久化并在刷新后继续以红色显示，P3 的同源首次 stale 可在 P1 终态后安全重试一次。它仍是测试候选，不能视为正式发布。来源映射见 [`docs/2.0/ACTOR_PROFILE_MVU_SEMANTIC_BRIDGE_SOURCE_MAP.md`](docs/2.0/ACTOR_PROFILE_MVU_SEMANTIC_BRIDGE_SOURCE_MAP.md)。

“通用”指核心只依赖当前 MVU 数据、动态 JSON Pointer、实际 Schema/规则和 SillyTavern
生命周期，不依赖某张角色卡、某组表名/列名、骰子 DOM 或缝合怪品牌。装备、骰子和
缝合标记的现有识别属于保守的 legacy 方言增强：出现明确合同信号时才启用；未知模板
仍可使用变量修复、完整身份门和 stale 零写入保护，但不会被猜测槽位、资源或标签。
TavernDB 检测也不读取表格内容、不调用数据库 API；真实表格 CRUD 只存在于隔离 QC
探针，用来证明黑盒共存，不会进入医生生产路径。

扩展代码，不会替换数据库、骰子前端、缝合怪、推进重roll助手或其他脚本。

每次收到新的 AI 回复后，扩展会：

1. 动态读取当前角色卡暴露的 MVU/Zod Schema。
2. 动态读取当前启用世界书中的 `[mvu_update]` 规则。
3. 等待本轮普通 MVU 更新稳定，避免在变量仍写入时抢跑。
4. 保留人物动机、自主性与关系证据账本；阶段一不再通过旧平行入口向真实主模型预生成注入，也不改写聊天正文。
5. 若本轮出现持久关系变化、极端关系标签、玩家隐藏动机归因、强制/自愿冲突、人格一句封死或同组极端标签堆叠，使用轻量通道做一次结构化语义二审；二审只能放行或恢复本轮关系路径并记录人物塑造提醒，不能改写正文文风。
6. 在开局窗口内检查“初始化满值、派生上限已提高、当前值却冻结”的资源失配，并用本地规则安全同步，不调用额外模型。
7. 对比上一 AI 楼层状态、当前 `stat_data`、本轮正文和原更新区块。
8. 针对规则明确带有死亡、逃跑、战斗结束、离队或失效清理条件的动态集合，按当前条目名定向回查历史证据；不会因为近期没提到就擅自删除。
9. 让模型只审计错更、漏更、动态成员资格、输入变化后的依赖闭包和装备/效果转移双方；`<content>` 只读，模型不得返回正文、选项或 swipe 修正版。
10. 在内存副本上校验路径、操作、MVU 解析和 Zod 结果。
11. 全部通过后才原子写入，并在写入后回读验证；社会关系回退、普通修复、开局同步和撤销共用同一写入队列，不能并发踩同一楼层。
12. 只把合法变量纠错块持久附加在当前 swipe 中，不会创建、覆盖或切换正文 swipe。
13. 刷新消息与 `<StatusPlaceHolderImpl/>`，让正文状态栏立即重建。
14. 变量修复继续生成自己的持久收据；旧世界注入收据只兼容保留，本阶段不新建注入批次。数据库只按每轮接受的 `<content>` 独立填表，不等待医生，也不会在变量提交后重填；世界、论坛和演员等附加任务不得阻塞正文或关键变量结算。重 Roll、换聊天或目标被替换时旧写任务会成为 `stale`，对应结果永久禁止写入。

v1.9.0 新增系统级人物动机与关系证据链。它不靠继续叠加“反绝望/反支配”形容词，也不把黑暗故事洗成温暖故事：本轮用户明确动机优先；NPC怀疑保留为有限视角；强制服从与自愿好感分离；普通照顾允许不改变关系；人物保留现实目标、边界和情绪恢复空间。平衡二审只在风险出现时调用轻量通道，输入限于本轮用户、正文、少量相关历史和关系差异，路径、理由与来源楼层均可追溯。rc.6 起不再估算模型价格、维护月度金额或因费用停止调用；服务费用由用户在所选服务商处自行管理。轻量模型HTTP成功但结构无效时按零关系写入处理并显示明确错误码。

模块职责、失败降级与追溯方法见 [`docs/SOCIAL_MOTIVE_GUARD.md`](docs/SOCIAL_MOTIVE_GUARD.md)。

v1.8.14 为副本、试炼、任务场与其他有边界场景新增“可版本化软规划”：首次建立主目标、完成/失败条件、原生终局冲突、路线、时限与赌注的不可覆盖基线；此后任何字段都可以被玩家行动、世界支线、既有设定或系统规则合理改变，但每次变化必须记录来源事件、触发、作用机制、证据、前后值和保留的既有成果。同回合临时生成的障碍不能伪装成长期世界因果来改写最终 Boss；真正经过多轮推进的支线则可以可追溯地引入更强敌人、打开捷径、取消冲突或改变通关方式。完成/失败后的同一规划不可复开，余波转为新的世界事件。悬浮事件账本可查看初始基线、当前版本和完整修订历史。v1.8.13 的复杂后台支线、动态汇流与真实注入校验继续保留。

副本规划的数据结构、门禁规则、追溯方法和必测正反例见 [`docs/VERSIONED_SCENARIO_PLAN.md`](docs/VERSIONED_SCENARIO_PLAN.md)。

v1.2.0 开始，每次任务还会绑定聊天 ID、稳定消息 ID、楼层、swipe、正文指纹和生成世代，并在每个异步步骤后复核。数据库预热/算 Token 的 `dryRun` 会被忽略；普通生成、swipe、regenerate 与 continue 分开记录。真正写变量时使用精确楼层而不是笼统的 `latest`，最大限度避免切聊天、重抽或连续生成时落错位置。v1.8.5 对世界/论坛的“整楼生成前”快照改用聊天内逻辑楼层识别，兼容宿主在 regenerate 时直接替换整条消息对象并生成新 ID；这只用于选择重抽基线，变量写入仍严格核对消息 ID、swipe、正文指纹和生成世代。

模型连接由扩展自己的“独立 API 连接与通道路由”管理；默认不借用酒馆当前主模型：

- 当前编辑连接可填写 OpenAI-compatible 端点、密钥和模型；支持从端点读取模型列表。
- 可保存多个带名称的连接预设，预设同时保存端点、密钥、模型、酒馆后端转发开关和“地址原样使用”开关。
- “严格变量通道”和“轻量人物 / 世界 / 论坛通道”各自拥有 1—8 个明确的并发槽位，默认分别为 2 个和 4 个。每个槽位都单独选择 API 预设，因此同一通道可以把请求分流到不同端点、密钥或模型，也可以重复选择同一预设来提高该 API 的并发额度。
- 每个槽位同一时间最多执行 1 个请求；超过槽位数的任务按轮转结果进入对应槽位的优先级队列。严格槽位与轻量槽位互不占用；人物分片、关系二审、世界连续性和论坛共享轻量槽位。供应商限流较紧时可以删减槽位，或把多个槽位分别指向不同供应商。
- “测试全部严格槽位”和“测试全部轻量槽位”会逐槽验证真实路由并标出失败槽位。多槽位只对扩展自己的独立兼容 API 生效；用户明确选择的酒馆当前连接仍强制串行。模型请求可以并发，变量提交、社会关系提交、世界账本与论坛持久化仍经过各自的身份复核和写入队列，不能并发踩同一楼层。
- 浏览器直连遇到 CORS 时可勾选“经酒馆后端转发”；这只是网络代发，不会改用酒馆当前聊天模型。
- 任一通道缺少预设、端点、密钥或模型时会明确失败，不会静默回退到酒馆当前模型或其他扩展。
- 变量检查失败后默认重试 3 次，可在“变量诊断与自动修复 → 模型适配、输出空间与提示词透明”中设为 0—5 次。这里填写的是“首次失败后的重试次数”，所以默认最多 4 次模型调用；所有尝试仍属于同一回合的一个自动主任务。

阶段一入口只在 SillyTavern 的一次最终接受、非空 AI 回复后分发既有模块；流式片段、加载回放、空占位、dry/quiet 和 stopped generation 不创建任务。各模块独立使用 chat/message/swipe/generation 身份去重，入口不等待、汇总或声明整链成功。旧的平行提示词注入暂时停用，等待后续批准阶段通过唯一入口重接。

活世界从 v1.8.8 起采用稀疏增量账本：模型只返回本轮改变的旧支线和新支线，未返回的旧支线由本地保留。既有注入队列、消费状态与历史收据继续兼容读取；阶段一不再创建或注册新的平行注入批次，也不在 generation 入口结算旧注入。它们要等后续批准阶段通过唯一入口重接。

“活世界与事件连续性 → 每回合最多注入正文的后台变化”在阶段一仅保留旧配置值，不会触发注入；后续重接时仍作为医生自己的上限，而不是正文配额。

自动入口在 SillyTavern 发出 generation ended、正文非空且页面不再处于生成态后重新读取最新 AI 回复，并用 generation started 前的快照确认目标确实变化；随后各模块独立启动，不等待 MVU、数据库或其他模块。变量模块在真正写入前仍执行自己的目标身份、MVU 状态和回读复核；手动检查也会在开始时读取最新回复。真正的新生成、切聊天、regenerate 与新 swipe 会使旧写任务失效。

v1.8.3 起，医生会从当前角色卡 Schema 变换和启用的 `[mvu_update]` 规则中动态识别自动计算字段。模型若仍尝试直接修改这些字段，本地会剥离对应操作，只让可写输入进入 MVU；前端基于输入合法重算的派生值不再被“未触碰字段必须不变”误杀。

v1.8.0 起，设置页的操作时间线和悬浮面板“工具”页会按当前聊天显示模型调用总数，并分别统计变量、活世界、论坛、失败和 429。统计只保存计数和时间，不保存正文、提示词、API 地址或密钥；切换聊天后读取该聊天自己的计数。

变量诊断默认使用 `8192 max_tokens`；设置页“变量诊断模型适配与输出空间”可以按所用模型实际允许的单次输出上限调整。医生只能输出一个完整 `<UpdateVariable>`。补丁 JSON 数组完整但中转遗漏尾标签时会本地安全恢复；任何正文修正、选项或 swipe 结构都按越权输出忽略，不会影响独立变量补丁的本地校验。

若宿主 MVU 对现有动态对象下的新成员执行细粒度补丁时静默漏项，医生不会立刻把同一正文重新发给模型。只有全部失败项都属于本次明确触碰、父路径是现有普通对象且没有任何无关字段丢失时，脚本才会把该父对象按原状态与已解析补丁机械重组，再送回同一个 MVU/Schema 解析器复验。复验仍失败、混有数组/只读/越权路径或旧字段损失时继续零写入并使用原有有限重试，不会用本地拼接绕过 Schema。

同一设置区还提供“附加破限/模型适配提示词”。医生仍自动构造 Schema、`[mvu_update]`、当前状态、初始化基线、正文、上下文和机器输出协议；这里只需粘贴模型适配的几句文字，留空即使用默认。

每次候选补丁除了核对明确触碰的路径，还会验证原状态中所有未触碰叶子字段仍被完整保留。解析器或新版 Schema 若意外剥离旧卡遗留字段，候选会在写入前被拒绝；新增的 Schema 默认字段仍允许保留。以 `_` 开头的只读字段，以及当前 Schema/规则明确声明为前端自动计算的普通命名派生字段，只允许在仍然存在时由 MVU 归一化重算，不能由模型补丁直接触碰，也不能被解析器删除；没有当前卡规则证据的普通字段不会被放行。

若普通 MVU 长时间保持“正在额外解析”且变量快照也无法稳定，医生会在 8 秒有界等待后以 `busy` 零写入跳过，并明确提示排查重复 MVU/变量脚本或刷新后直接检查当前回合；不要求重 roll 正文。变量、人物关系、世界和论坛的用户可见错误都会显示“问题”与“怎么解决”，并说明是否写入、是否阻塞其他功能。若写后回读失败，回滚只恢复本次补丁实际触碰的路径，保留其他插件或普通 MVU 同期产生的合法状态，并以语义子集而非整树字符串指纹对回滚结果再次确认；宿主重排键或补充 `display_data`/版本字段不会造成假失败。

每次真正写 MVU 之前会先保存带快照、触碰路径和前后路径值的恢复记录，并等待宿主的 `saveMetadata` 或 `saveChat` 完成后才调用 `replaceMvuData`；只有不可等待的防抖保存接口时会安全取消变量写入。写入通过回读后把同一记录升级为已应用，最后才尝试把纠错块附加到原 swipe。即使用户恰在异步写入飞行中切换聊天/swipe，已经落地的变量变化也不会被误报成“未写入”，新回复不会被读取或刷新，回到原目标后仍可核验并撤销。撤销只恢复该次修复触碰的路径，其他插件后来新增的显示、版本或无关状态继续保留；若写入根本没有落地，预备记录会识别为无需撤销。正文刷新成功后，同一日志记录才标记为已同步。

## 必须这样设置

- 安装后先打开设置页顶部“环境自检”。它会只读检查 MVU API 和医生自己的模型连接，并明确显示阶段一旧平行注入已停用；自检不会修改其他扩展设置、角色卡或世界书。
- 关闭 MVU 的“额外 AI 解析/额外模型更新变量”。本扩展跟随角色卡原本的 `<UpdateVariable>` 更新完成后再审计，不需要第二个 MVU 解析模型。
- SP·数据库继续使用作者原版字段和填表提示词。自动医生不读写数据库表，也不接管数据库回忆，不要求数据库注册任何医生协议。数据库每轮只读取接受的 `<content>` 独立填表，不等待变量医生，也不会在变量写入后重新触发。`2.0.0-rc.2` 起已删除旧“数据库最终正文桥”；旧安装若仍保留该 TavernHelper 条目，应将其禁用或删除。
- 同一角色只启用一套当前版本的 MVU 更新规则。若作者卡已内嵌世界书，不要再同时启用一套重复旧世界书。

“关闭 MVU 额外 AI 解析”只针对 MVU 自带的第二次变量解析。活世界与事件连续性开启时，会在主回复落地后使用插件连接整理一份独立的因果账本，但它不写 MVU，也不代替角色卡原本的变量更新。

## 开局资源初始化修正

设置中的“开局自动补满初始化失配的资源”默认开启。它用于修复这类角色卡错误：世界书把资源初始化为满值（例如 MP 50/50），角色创建完成后前端把上限派生为 110，却只留下当前值 50。

- 只在当前聊天最前面的 4 条 AI 消息内运行，包括角色卡开场白。
- 优先读取当前激活世界书的 `[initvar]`/“变量初始化”条目；存在外置条目时以其为权威，不再混用卡内嵌副本。没有外置条目时读取卡内嵌初始化；两者都不可读时，才用上一楼确实满值的状态作证据。
- 不写最大值，只把已证明属于初始化失配的“当前值”同步到现有最大值。
- 明确 initvar 满值证据不依赖 HP、MP 等专属字段名，会识别中英文“当前/最大/上限”成对字段，因此可用于其他 MVU 卡；只有缺少 initvar、退回“上一楼满值”单证据时才要求字段具备通用资源语义。
- 初始化不是满值的容量字段不会动，例如负重 0/55；本轮更新区块明确改过的资源也不会动，因此不会把战斗消耗或主动施法误判成开局补满。
- 同时识别 `MP_当前/MP_上限`、`HP当前值/HP最大值`、`MP:{当前,上限}` 和数组内角色资源等常见通用结构；YAML `- 名称: 术士` 块序列及 `- 属性:` 下的嵌套映射会按缩进解析为数组对象，嵌套映射后的同级字段不会被误吞，initvar 数字后的行内注释也不会把数值误解析成字符串。所有形态仍须满足可验证的开局满值证据，`0/0` 视为尚未建立正上限，不会在派生为 `0/5` 时自动补满。
- 仅凭上一楼满值推导时会排除任务进度、阶段、次数等非资源计数，避免把 `3/3 → 3/5` 的新阶段误补成完成；只有明确 initvar 证据才能覆盖这项保守排除。
- 多阶段捏人再次提高上限时，只要该资源仍保持上一步同步后的满值，可以在开局窗口内继续同步。
- 每次修正同样经过 MVU 解析、Schema、精确楼层写入、写后回读和可撤销记录，不是仅修改前端显示。

## 活世界与事件连续性

该功能不会强行在正文末尾公开所有幕后事件，而是把状态保存在当前聊天的插件元数据中。阶段一只保留账本处理，不向下一回合注册旧平行提示词注入。v1.6.0 起，医生在原有连续性账本之上增加事件时钟和分类世界快照；“平行事件”不是正文衍生支线的同义词，而是四类并存的活世界事件：

rc.5 把 Actor Shard 升级为稳定身份与生命周期可审计的持久人物账本。人物不再只是已有事件里的临时候选：
重要、次要和低关注人物会保存自己的身份、性格与底线、目标、有限认知、位置、资源、
能力、关系、承诺、隐藏情绪惯性与冲突、计划、上次行动和下一行动窗口。每轮按到期、
主动性、机会、时限、承诺、资源与沉默轮数选1—5人，另可保留0—2个低关注探索槽；
休眠人物不会删除，出现新机会会重新唤醒，连续有效行动还能逐步升格。

每个隔离 worker 仍只产严格 JSON 候选。候选必须通过本地身份、知识、时间、地点/
旅行、资源、能力、因果、证据和玩家主权校验；人物不能替玩家说话、移动、消费、
接受或服从。合法行动先进入人物账本和 hidden/可观察世界事件，只有来信、来访、
公告、价格、交通、舆论、袭击等真实可观察后果才进入现有汇流与注入预算。逐条收据
记录“计划→执行→世界结算→注入→正文消费/保留”。失败、超时或拒绝只降级人物
附加模拟，不阻塞正文、数据库、变量医生或世界本地时钟。

活世界同时保留独立势力轨和环境轨。势力、环境、设施、机制、经济、长期趋势、
公共信号和因果余波不需要被硬塞给某个NPC代表，也不会因为没有人物候选、关闭人物
分片或人物worker失败而停止。三个通道只在统一世界结算处汇合，共享阶段压力、
同场首领、恢复债务、注入数量、优先级、时效和字符预算；正文仍可采用0条。

设置页另提供“世界连续性”和“NPC分片”两个最长6000字符的用户自由提示词插槽。
内容不做题材/NSFW语义过滤，也不附带默认破限文本；它只能影响叙事与模拟候选，
不能覆盖玩家授权、事实证据、事务、危险确认、分支、数据库屏障或硬字段校验。
脱敏诊断只导出是否启用、长度和哈希，不包含全文。

推进结构参考了 [DlSNlGHT/World](https://github.com/DlSNlGHT/World) 的实际源码机制，包括事件阶段内进度、风声衰减、稳定 ID 增量合并和条件筛选注入；本扩展不依赖或安装该项目，也不沿用其题材化文案和复杂配置界面。

- `主线衍生`：由正文中已经发生的行动、人物或因果直接产生。
- `世界设定·暗中相关`：尚未在主线露面，但按世界设定存在潜在因果，等待真实传播链或接触条件。
- `世界设定·当前独立`：依据角色卡/当前世界书独立发展，可能很久以后自然相交，也可以永远不相交。
- `世界脉动`：组织、社会、生态、日常生活或局势在玩家视野外自行变化，可以在幕后自行结束。

运行规则：

- 识别预设的 `<parallel_event_record>`、`<current_event>`，以及缝合怪的 `<dm_story>`、`<npc_track>`。
- 给事件保留稳定 ID、冲突/事务类型、1–4 级规模、阶段内 `1/9` 至 `9/9` 进度、来源类型、因果父项、与主线关系、幕后变化、触发条件、下一拍、自然汇流条件、知情层级、持续影响、流言与设定依据。
- 每个完成的 AI 回合都会先由本地事件时钟为所有未结事件给出“推进／保持／受挫”基线；冲突等级越高越容易升级，事务等级越高越难完成，连续不成功达到上限后会保底推进。模型再依据真实能力、资源、信息、距离和阻力复核，可标记暂时受阻或按明确因果终结，不会为了机械推进凭空补条件。
- 若切换页面、长生成或插件队列让若干 AI 楼层尚未落账，下一次调度会按 `lastSource` 一次补记所有漏掉的完成回合，而不是只处理最新一楼；旧 v2 账本会继续迁移使用。
- 当世界模型遇到 429、超时、空响应或坏 JSON，本地事件/传播时钟已经产生的变化仍会保存并明确标记降级，不再把整轮回退成“未产生有效节拍”。
- 一轮通常调度一个相关事件簇：活世界模式允许同簇最多3条、活跃模式最多6条旧事件产生新的实质叙事变化；簇外事件只更新时钟压力，不要求全部进入正文。若正文只过去片刻、时间窗未到或因果前提未满足，可以登记带有具体依据的 `held`。空泛的“无变化”不算有效调度。
- 玩家本轮 A 行动直接造成持续 B 影响时，可以在推进旧事件的同一回合登记 main_derivative 事件 C；不再发生“推进旧事件就丢掉新因果”的二选一。
- 事件结束时必须登记结束方式和至少一项持续影响或流言。仍会自行发展的 D 后果使用 `causedBy` 派生新稳定事件；旧事件保持 resolved，避免把同一支线无限续命。
- 预设反复输出同一平行事件标记时，只更新真正出现的新事实；既有结束方式、持续影响、流言、知情层级、紧迫度和创建回合不会被空默认值抹掉。
- 世界整理仍限制单个相关事件簇产生新事实；面向下一轮正文的旧注入层在阶段一停用，候选与旧配置只兼容保留。
- 人物轨和非人物结构世界轨分开占用有界调度位置。势力、环境与经济不要求先找到一个NPC代言；人物模拟失败时结构世界轨和原事件时钟继续运行。
- 分类世界快照分为长期趋势、势力、风声、声誉、环境、隐秘和因果联动。声誉使用“机构／公众／地下圈层／专业圈层”，所有名词与例子取自当前角色卡和世界书，不预设古代、现代、赛博或奇幻文案。
- 世界模型只返回本轮有实质变化的字段；本地按稳定 ID 增量合并，未返回的旧势力、风声或隐秘不会被整块覆盖。新条目由本地分配 ID，模型编造的未知 ID 会被拒绝。
- 世界推演按“私密性 → 长期趋势 → 新风声 → 传播节点 → 覆盖圈层 → 跨类别影响 → 声誉/敌情/经济”的顺序检查。无目击、未留痕迹的私密行为只留在隐秘分类，不会直接变成公共声誉或让不知情 NPC 行动。
- 不同类型的风声有不同沉寂宽限与衰减速度；只有出现新的合法传播节点才能扩大强度或范围。跨类别变化必须登记因果联动，经济和声誉单轮最多移动一级。
- 分类状态、隐藏条目、低传播风声与尚未汇流的独立事件都继续留在账本；阶段一不会把它们注册为下一回合提示词。
- hidden / rumor / observed 分层，禁止让不知情角色突然全知。
- 只推动 NPC、势力、敌方、环境、约定与离场角色；禁止替玩家角色行动、回答、移动、消费资源或追加检定。
- 检测到预设或缝合怪时采用桥接模式，由原系统保留剧情提案权；插件只做接续、去重和回收。
- 缝合怪的成功/失败路线保留为条件式导演提案，不作为裁决目标。先按当前骰子前端的固定位置或顺序消费唯一骰值并结算 DC/成功等级，再选择对应剧情分支；禁止浏览骰池挑成功数字或先写结果后补造检定。
- 检测到 DlSNlGHT/World 世界引擎时同样进入桥接模式：世界引擎保留事件链、风声与世界推演提案权，变量医生不再把自己当唯一导演，只补缺失因果并避免同一事件重复推进。
- 自主事件只从当前角色卡与当前启用世界书的叙事设定取材，可创建符合设定的普通 NPC、小组织和地方事务，但不能凭空改写核心世界观或重要角色过去。
- 独立事件默认只在幕后账本推进，不为了展示伏笔强塞进正文；只有传播、因果、人物接触、地点或时间条件真实满足时，才先进入“正在汇流”。
- hidden 且尚未汇流的事件向主回复只暴露稳定 ID、阶段和调度边界，连语义化标题也会折叠；最近调度的 `lastTick.reason` 同样替换为不含幕后事实的通用说明，不能绕过标题折叠。事件在幕后结束后，其标题、结束方式、持续影响与流言也继续留在后台账本，直到知情层级或真实汇流条件允许公开。标题与幕后细节只保留在玩家主动打开的审计视图中。
- 独立事件允许一直不与主线相交，也允许在幕后解决。结束后的影响和有传播链的流言会继续保存在世界状态中并可派生后继事件；只有公开条件满足后才进入主回复，插件不会把所有变化都变成围绕玩家的任务。
- 已结束事件进入独立归档容量，不再占用活动事件槽位；长期游玩不会因为历史事件塞满上限而停止生成。

模式说明：

- `自动活世界（推荐）`：有角色卡/世界书叙事设定时即可在回复后维护活世界；检测到预设/缝合怪时自动桥接去重。
- `始终开启`：没有结构化标记时也整理正文中的明确未决因果。
- `关闭`：撤下注入，不运行世界整理；已有账本仍保留，除非手动清空。

自主度说明：

- `保守`：只登记正文、预设或缝合怪已经提出的因果，不主动建立幕后事件。
- `活世界（推荐）`：自主新事件至少间隔 3 个账本轮次，最多保留 3 条未结自主事件。
- `活跃`：自主新事件至少间隔 2 个账本轮次，最多保留 4 条未结自主事件。

重抽或重新生成时，正文生成阶段使用该楼回复产生前的世界/事件存档点；新 swipe 落地后再从存档点重算，不让被放弃的旧 swipe 污染新剧情。即使 TauriTavern 在同一楼 regenerate 时不是增加 swipe，而是用新 `send_date`/新稳定 ID 替换整条消息对象，也仍按逻辑楼层命中原始存档点，不会沿旧正文账本继续推进。

阶段一不再监听 `MESSAGE_SWIPED` 执行回退，也不在下一次生成开始时自动恢复存档点；切换、加载和刷新聊天只读。既有检查点继续保留，只能从对应模块的明确手动恢复入口使用。hidden 且尚未显现、未汇流的 independent/latent 事件仍不能仅凭模型声称升级成公开传闻，论坛取材处保留本地闸门。

当前候选为每个最新 AI 楼层保留一个“整楼生成前”世界/事件/论坛存档点，而不是保存该楼每个既有 swipe 的完成后账本快照。因此，手动切回一个已经看过的旧 swipe 时会保守回到整楼生成前状态，防止另一分支的事件或帖子串入；它不会即时还原那个旧 swipe 当时生成后的账本。后续真正生成/续写时会按当前分支重新结算。需要逐 swipe 浏览历史时，应等未来引入按稳定 swipe 身份保存的有界快照，不能复用另一分支结果冒充。

活动线程超过设置容量时不会再被截断删除：超出的未结因果转为 `dormant`，保留触发条件、因果链和审计卡片，并在界面显示休眠保留数量；提高容量或调度条件成熟后可以重新唤醒。事件仍只有在登记 resolution 与持续影响/流言后才进入 resolved。

## 手机前端

设置页、贴边悬浮球、世界/事件/论坛/工具四分页和完整论坛共用同一套主题色、状态条、圆角与触控规范。世界页先显示一段摘要，再把长期趋势、势力、风声、声誉、环境、隐秘和因果联动分别放进默认收起的分类栏；事件详情留在独立页，摘要只显示阶段与紧迫度，展开后按“当前 / 因果 / 传播与收束”分组且隐藏空字段。设置页各功能区默认折叠，完整事件账本只在悬浮面板保留一份。悬浮球贴到左右边缘后，计数角标会自动翻到屏幕内侧，不会被手机边缘裁掉；长按约一秒可把位置恢复到默认值。

## 世界论坛

“打开独立论坛”可以直接打开扩展自带的论坛。论坛以当前聊天为单位保存帖子、评论、版块、热度与刷新页次，并使用独立模型请求增量刷帖，不占正文篇幅、不写 MVU、数据库或事件账本。v1.6.0 起默认改为手动刷新：论坛标题栏始终保留“刷新论坛”按钮；手动/自动切换、自动间隔和清空操作放在默认收起的“刷新与管理”中，不再占据手机阅读首屏。

- 首次刷新生成 4 至 5 个帖子和 6 至 12 条评论，每个首屏帖子都至少有一条回复；后续每次生成 2 至 4 个新帖和 6 至 12 条评论，并优先给零回复旧帖补楼。
- 至少一半内容是日常闲聊、求助、攻略、交易、吐槽、八卦或地方话题；不同网友会补充、质疑、开玩笑或跑题，不把整个论坛变成任务板。
- 生成结果若帖子或评论数量不足、首屏仍有孤帖、后续没有补零回复旧帖，会自动拒绝并重试一次，不把不合格的一页保存到聊天。
- 只把 observed / rumor 等已经具备公开传播条件的世界风声交给论坛；hidden 幕后事件和私密正文不会泄露给网友。
- 论坛模型不直接接收最近正文或完整世界书；世界设定只允许带有公开、常识、地理、交通、制度、生活、新闻等公共语义的条目进入取材池，标题、关键词或正文含秘密、幕后、真相、未触发和剧透信号的条目都会在本地过滤，中英文 `GM/DM eyes only`、`do not reveal` 等写法同样拒绝。
- 模型偶尔漏写数组/对象项之间的逗号或多写末项尾逗号时，本地会在不改变任何字段内容的前提下安全修复标点；修复成功会明确显示。输出被截断、缺字段值或结构不确定时仍会拒绝整批，不会把半截论坛写入聊天。
- 普通帖子永远留在论坛。只有帖子已经造成持续的聚集、传播、短缺、人物决定或外部行动时，下一轮支线调度才可把它登记为因果事件；网友猜测不能倒推成真相。
- 支线与论坛之间的既有账本关联继续保留；把结果重新注入正文的旧平行入口在阶段一停用，等待后续唯一入口重接。
- 默认手动刷新；普通 AI 回合和打开空论坛都不会暗中调用论坛模型。点击论坛标题栏或设置页的“刷新”才生成一页。
- 可切换为按 AI 回合自动刷新，并把间隔设为 1 至 12 回合；旧版自动刷新配置升级到 v1.6.0 时会安全迁移为手动，避免升级后继续产生用户未预期的调用。
- 重抽会使用该楼刷新前的论坛存档点，旧 swipe 生成的帖子不会污染新回复；切换聊天后只显示新聊天自己的论坛。
- 同一楼层使用 continue 续写时保留整楼生成前的论坛与支线存档点；之后 regenerate/swipe 仍从整楼开始前重算，不会把续写中间态带进新分支。
- v1.8.1 起，同一 swipe 的多段 continue 合并为一个显示回合：活世界只推进一次，自动论坛也只刷新一次。续写仍会重新检查最终正文与变量，但不会按片段重复收取世界/论坛模型费用。

### 手机端查看活世界账本

安装后默认出现一个写有“脉”字的悬浮球，也仍可在“扩展设置 → MVU 自动医生（通用）→ 活世界与事件连续性”查看同一份账本：

- 悬浮球可上下拖动，松手后吸附到最近的左右边缘，闲置时只露出一小段；点击即可拉出并打开面板。位置会保存在本机。
- 角标显示当前未结事件数；整理中、成功或失败会使用不同的光效提示。可在扩展设置关闭悬浮球，状态栏入口始终保留。
- 悬浮面板分为“世界 / 事件 / 论坛 / 工具”四个页签并记住上次所在页。世界页内部再按类别折叠，事件卡和工具不会与世界摘要纵向堆叠。
- 面板提供“检查变量”“检查硬规则”“整理世界”和论坛入口。论坛入口直接进入移动端完整论坛，空页面会等待用户手动刷新。

- 顶部显示未结数、已收束数、账本轮次、更新时间和当前来源模式。
- 未结事件按“已显现 → 推进中 → 已埋设 → 搁置”及紧迫度排序；第一条不含剧透的事件默认展开。
- 尚未在主线显现的独立事件默认只显示“幕后独立事件（点击查看剧透）”，避免玩家提前失去惊喜；可关闭剧透折叠。
- 点击每条事件可查看来源、因果父项、与主线关系、设定依据、当前进展、幕后变化、结束方式、持续影响、传播中的流言、下一自然接口、触发条件、汇流条件、人物地点、知情范围和最近来源楼层。
- 已收束事件放在单独的折叠区，不与活动事件混在一起。
- “风声”分类只汇总已经形成传播链的消息。普通水帖、吐槽、玩笑和日常互动不是世界事件，继续由卡内贴吧或独立论坛生成。
- “刷新显示”只重读当前聊天元数据，不调用模型；“立即整理世界”才会调用模型更新账本。
- 该区域是玩家审计视图；只有你主动展开剧透卡片时才显示角色尚不知情的幕后信息，插件不会因此把隐藏知识泄露给正文角色。

切换聊天、收到新回复、整理完成、重抽或清空账本后，显示会自动刷新。选择“关闭”只停止后续整理，旧账本仍可查看。

扩展设置里提供：

- 自动开关
- 开局初始化资源满值同步开关
- 可保存多个端点/密钥/模型的独立 API 预设、模型列表获取与逐并发槽位双通道路由
- 变量诊断单次输出上限与附加破限/模型适配提示词
- 写前目标身份与写后回读保护
- 回复后等待时间
- 手动检查最新回复
- 跨刷新保存、并经过变量指纹保护的撤销记录
- 活世界的自动兼容/始终开启/关闭模式
- 活世界自主度与幕后事件剧透折叠
- 手动整理世界与清空当前聊天账本

插件不包含任何角色卡专属字段、路径或枚举。角色卡更新或切换到其他 MVU 卡时，会重新读取新卡的规则和 Schema。

聊天元数据只保存有限条修复快照、活世界/事件账本、内置论坛帖子和来源指纹，不保存 API 密钥或完整模型提示词。单条 MVU 快照超过安全体积时不会写入聊天，此时该条修复仍然有效，但无法跨刷新撤销；日志仍会保留该记录，重载后点击撤销会明确说明“快照过大”，不会假装没有发生过修复。
